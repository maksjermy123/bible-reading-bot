# 📖 План чтения Библии — Telegram Mini App

Статическое мини-приложение для Telegram WebApp: планы чтения Библии по
перикопам, трекер дней подряд, напоминания и синхронизация прогресса между
устройствами. Живёт на GitHub Pages, бэкенд общий с проектом MyRadio:
`https://myradio-rrsk.onrender.com` (репозиторий maksjermy123/MyRadio).

## Возможности

- **3 готовых плана по перикопам**: Новый Завет за 90 дней, Библия за год,
  Хронологический план за год. День никогда не разрывает перикопу.
- **Хронологический НЗ** с произвольной длительностью 30–365 дней: нарезка
  событий на лету без разрыва перикоп.
- **Свой план**: выбор книг + длительность, нарезка по перикопам выбранных книг.
- **Экран чтения**: заголовок перикопы над текстом, разделители глав,
  корректный рендер отрезков, пересекающих главы (`{c1,v1,c2,v2}`).
- **Копирование стихов**: тап по номеру — начало диапазона, тап по второму
  номеру — конец. Работает и через границы глав (межглавный выбор копируется
  блоками `[Книга N]`, ссылка охватывает весь диапазон), плюс нативное
  выделение текста системным способом.
- **Темы оформления**: Авто / Светлая (тёплая кремовая) / Тёмная. Устаревшие
  темы мигрируют автоматически (light→sepia, night→dark).
- **Шрифты** Inter / Source Serif 4, ползунок размера текста, номера стихов
  вкл/выкл, тактильный отклик на ключевых действиях.
- **Закладки**, статистика стрика, milestone-экраны, синхронизация прогресса
  через бэкенд (Supabase) c офлайн-фолбэком в localStorage.

## Файлы

| Файл | Роль |
|---|---|
| `index.html` | Всё приложение: UI, логика, встроенные данные перикоп и хронологии |
| `plans.json` | Расписания планов (грузится асинхронно, кэш localStorage `pp_ver/pp_data`) |
| `bible_synodal.json` | Полный текст Синодального перевода |

Данные перикоп внутри `index.html`: `PERICOPE_ENTRIES/TITLES` — карта всех
1270 перикоп (100% покрытие, 31 162 стиха); `NT_CHRONO_U_PERI/TITLES` —
443 хронологических юнита НЗ с заголовками эпох.

## Деплой

1. Заменить `index.html` (при изменении расписаний — также `plans.json`).
2. Если менялся состав расписаний в plans.json — поднять версию:
   в index.html `var PLANS_PERI_VER='vN'` → `'vN+1'` (инвалидация кэша).
3. Проверка после заливки (Pages кэширует ~10 минут):
   - открыть `https://maksjermy123.github.io/bible-reading-bot/index.html?v=N`
   - убедиться, что исходник страницы заканчивается на `</html>`
     (CDN обрезал файл при размере >900 КБ — текущая сборка ~296 КБ, безопасна).

## API бэкенда (используемые маршруты)

Все личные запросы подписаны Telegram initData (HMAC), проверяются на сервере:

- `POST /plan/register`, `GET /plan/status`, `POST /plan/read|unread`,
  `POST /plan/unregister`, `/plan/settings` (время напоминаний),
  `/plan/merge_days`, `/plan/set_days` — прогресс и настройки;
- `GET /account/status` — статус аккаунта/reset-token;
- `GET|POST /state` — облачное хранилище настроек приложения.

## Напоминания (реализованы на бэкенде, см. репозиторий MyRadio)

Минутный cron по МСК рассылает по выбранному пользователем времени:

1. **Старт нажат, план не выбран** — мягкая цепочка из максимум 5 сообщений:
   первое через 2 дня после Стартa, далее каждые 3 дня, кнопка «Выбрать план».
2. **План выбран, но не прочитан ни один день** — дружелюбные онбординг-тексты
   в зависимости от возраста плана («план ждёт тебя уже N дней»).
3. **Обычный режим** — если сегодня ещё не читал: «🔥 N дней подряд» либо
   предупреждение об отставании (число дней считается по тому же алгоритму,
   что в мини-аппе). Прочитал сегодня — сообщение не приходит.

При 403 от Telegram напоминания автоматически отключаются для всех планов.
